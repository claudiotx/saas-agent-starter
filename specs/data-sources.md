# Data Sources and Dependencies

> **Example content** for the made-up SignalDeck project. Step 1 replaces it.

Everything the project needs from outside the repo: services, accounts, keys, assets and
decisions that belong to someone else. Agent 1 must list each one with an owner and a status,
so the Manager never discovers a missing dependency mid-build.

## External services

| Dependency | Used for | Needed by | Owner | Status | Dev and CI substitute |
|---|---|---|---|---|---|
| PostgreSQL | All app data | Phase 1 | Manager (local Docker) | Available | Docker Compose container |
| S3-compatible storage | Media files | Phase 3 | User creates the bucket for production | Dev: available. Prod: **needed from user** | MinIO container |
| Stripe account (test mode) | Subscriptions | Phase 7 | User | **Needed from user** (test keys) | Stripe test mode with `stripe-mock` for unit tests |
| Transactional email provider | Verification and invite emails | Phase 2 | User | **Needed from user** (API key) | Console or MailHog in dev and CI |
| Domain and TLS | Production hosting | Release only | User | Not needed to build | Not applicable |

"Needed from user" items must be resolved or substituted in Step 1. If production access is not
available during the build, the Manager builds against the substitute and the pull request
says what must be configured at release.

## Secrets and configuration

| Variable | Purpose | Where it comes from |
|---|---|---|
| `DATABASE_URL` | Postgres connection | Local Docker default, production from the host |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Media storage | MinIO locally, provider in production |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Billing | Stripe dashboard (test keys for build) |
| `EMAIL_API_KEY` | Sending email | Provider dashboard |
| `SESSION_SECRET` | Signing session cookies | Generated, 32+ random bytes |

Only `.env.example` (names, no values) is committed.

## Content and assets

| Item | Source | Status |
|---|---|---|
| Product name and logo | Placeholder wordmark in text | Final logo not required for build |
| Sample media for tests (one JPG, one H.264 MP4 under 5 MB) | Generated by a script or a licence-free sample | Manager creates in `tests/fixtures/` |
| Plan price (per screen per month) | Business decision | **Assumed** 9 USD, stored as a Stripe price ID in config, easy to change |

## Source of truth

| Item | Where | Rule |
|---|---|---|
| Requirements | `specs/mission.md` | If a later instruction conflicts, the later instruction wins, and the change is noted in a commit message. |
| Database shape | `src/db/schema.ts` and migrations | Never edited by hand in a database. |
| Plan and prices | Stripe (test mode in build) | App reads the price ID from config. |

## Data handled

| Data | Sensitivity | Rule |
|---|---|---|
| Email, hashed password | Personal | Hash with Argon2id, never log. |
| Customer media | Customer confidential | Private bucket, signed expiring URLs only. |
| Play logs | Business | Scoped by organisation, retained 90 days. |
| Payment details | Highest | Never stored here. Stripe holds them. |
